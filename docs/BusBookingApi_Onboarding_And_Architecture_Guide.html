Section 2: Detailed Explanation of What the Application Does

2.1 Business Purpose & Core Functional Flows

BusBookingApi is a high-throughput backend Web API that powers an intercity bus ticket reservation system. It supports five core functional workflows:

  1. Authentication & User Lifecycle (AuthController): Users register accounts with passwords hashed via BCrypt (cost factor 12) and log in to receive a signed HMAC-SHA256 JWT Bearer token (120-minute expiry) plus a 7-day refresh token. Administrators and Managers can audit user accounts, and Administrators can remove accounts.
  2. Bus Vendor Management (BusBookingController): Manages bus operator companies (e.g., Greyhound Express, MegaBus Lines, PeterPan Coach), their contact numbers, email addresses, and active status.
  3. Locations & Boarding/Drop-off Points (BusBookingController): Manages city terminals (BusLocations with unique station codes such as NYC, BOS, DC, PHI) and specific boarding/drop-off points (BusAddressLocations) within each city. Location queries are cached in HybridCache for 60 minutes.
  4. Schedule Publishing & Fast Bus Search (BusBookingController): Operators publish schedules with origin, destination, travel date, departure/arrival times, price, and total seat capacity. Customers search routes via Dapper queries backed by SQL covering indexes and 2-minute HybridCache entries that dynamically compute availableSeats = totalSeats - bookedSeats.
  5. Atomic Seat Reservation & Cancellation (BusBookingController): Customers book specific seat numbers for one or more passengers. The system prevents double-booking using both a SERIALIZABLE transaction in EF Core and a unique clustered index on the schema-bound view dbo.vw_ActiveScheduleSeats.

2.3 Database Schema, Covering Indexes & Concurrency-Safe Indexed View

The SQL Server database BusBookingDb contains 7 relational tables and 1 schema-bound indexed view:

  • dbo.Users — Stores user credentials, BCrypt hashes/salts, roles (Admin, Manager, Associate, Customer), refresh tokens, and RowVersion concurrency token.
  • dbo.BusVendors — Stores bus operator companies and IsActive status.
  • dbo.BusLocations — Stores city terminals and unique station codes (UQ_BusLocations_Code).
  • dbo.BusAddressLocations — Stores boarding/dropping landmarks linked to BusLocations (ON DELETE CASCADE).
  • dbo.BusSchedules — Stores scheduled bus trips, pricing, seat counts, and covering index IX_BusSchedules_Search.
  • dbo.BusBookings — Stores booking headers linked to customer and schedule with status (Confirmed / Cancelled).
  • dbo.BusBookingPassengers — Stores individual passenger records and assigned seat numbers (SeatNo).
  • dbo.vw_ActiveScheduleSeats (Indexed View) — Schema-bound join of BusBookings (where BookingStatus = 'Confirmed') and BusBookingPassengers with a Unique Clustered Index on (ScheduleId, SeatNo). This guarantees at the database engine level that no two active bookings can ever occupy the same seat on the same schedule, while still allowing a seat to be re-booked if an earlier booking is cancelled.

2.4 Enterprise Non-Functional Capabilities (NFRs)

  • Rate Limiting (Microsoft.AspNetCore.RateLimiting):
    • fixed-general: 100 requests per minute (Fixed Window).
    • sliding-search: 60 requests per minute across 6 segments (Sliding Window) on searchBus / searchBus2.
    • token-booking: 10-token bucket replenishing 1 token every 2 seconds on PostBusBooking.
  • Caching (HybridCache): L1 in-memory cache with stampede protection for locations (60-min TTL) and bus search results (2-min TTL).
  • Resilience (Polly v8 + EF Core Retry): Exponential backoff with jitter on transient failures and SQL Server retry-on-failure strategy.
  • Observability (OpenTelemetry & Serilog): Custom meter BusBooking.Monitoring tracking bus_bookings_created_total, bus_seats_booked_total, and bus_booking_failures_total, paired with structured Serilog console logging.
  • Global Exception Handling (RFC 7807): Maps ValidationException -> 400 Bad Request, NotFoundException -> 404 Not Found, SeatAlreadyBookedException -> 409 Conflict, and unexpected exceptions -> 500 Internal Server Error with traceId.

Section 3: Step-by-Step Instructions to Run the Application Locally

3.1 Machine Prerequisites

  • .NET 10 SDK (v10.0.100 or newer) — Verify by running dotnet --version in PowerShell.
  • Microsoft SQL Server (Developer, Express, or Enterprise Edition running locally on localhost) and sqlcmd utility.
  • Windows PowerShell 5.1+ or PowerShell 7+.
  • IDE: Visual Studio 2022/2026, VS Code with C# Dev Kit, or JetBrains Rider.

3.2 Step 1 — Open PowerShell & Navigate to the Workspace

cd C:\Projects\BusBookingApi

3.3 Step 2 — Verify Connection String & JWT Settings

Open C:\Projects\BusBookingApi\src\BusBooking.Api\appsettings.json and confirm the SQL Server instance name matches your local SQL Server installation:

{
  "ConnectionStrings": {
    "DefaultConnection": "Server=localhost;Database=BusBookingDb;Trusted_Connection=True;TrustServerCertificate=True;"
  },
  "JwtSettings": {
    "Secret": "SuperSecretKeyForBusBookingApiMustBeAtLeast32BytesLong!",
    "Issuer": "BusBookingApi",
    "Audience": "BusBookingClient",
    "ExpiryMinutes": 120
  }
}

3.4 Step 3 — Initialize & Seed the SQL Server Database

Run the DDL and seed script using sqlcmd (creates BusBookingDb, all 7 tables, covering indexes, the dbo.vw_ActiveScheduleSeats indexed view, sample locations, and vendors):

sqlcmd -S localhost -E -i "C:\Projects\BusBookingApi\scripts\01_Initial_Schema_And_Covering_Indexes.sql"

Alternatively, you can apply EF Core migrations directly:

dotnet ef database update --project "src\BusBooking.Infrastructure\BusBooking.Infrastructure.csproj" --startup-project "src\BusBooking.Api\BusBooking.Api.csproj"

3.5 Step 4 — Build & Run the Application

Build the full solution and start the API server on port 5241:

# 1. Build the solution
dotnet build "C:\Projects\BusBookingApi\BusBooking.slnx"

# 2. Start the Web API
dotnet run --project "C:\Projects\BusBookingApi\src\BusBooking.Api\BusBooking.Api.csproj" --urls "http://localhost:5241"

If setting up the database for the first time, seed the default Admin, Manager, and Associate accounts by running:

powershell -ExecutionPolicy Bypass -File "C:\Projects\BusBookingApi\scripts\seed_users_via_api.ps1"

3.8 Step 7 — Troubleshooting Guide for New Engineers

  • Build Error (BusBooking.Api.exe is locked by another process): Stop the running API process before compiling:
    Get-Process -Name "BusBooking.Api" -ErrorAction SilentlyContinue | Stop-Process -Force
  • PowerShell 5.1 Invoke-WebRequest Hanging: Always include -UseBasicParsing when using Invoke-WebRequest in Windows PowerShell 5.1 so it does not invoke the legacy Internet Explorer MSHTML DOM parser.
  • Swagger UI 401 Unauthorized After Restart: Press Ctrl+F5 in your browser to ensure Swagger UI reloads the latest /swagger/v1/swagger.json security definition.
